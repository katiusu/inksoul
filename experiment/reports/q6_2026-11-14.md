# Q6 首轮：生成期控制 vs 裸生成（2026-11-14）

模型 `deepseek-chat`（实际响应 model=`deepseek-flash`）｜10 组 brief｜目标 800 字｜
花费 ¥0.18（余额 6.81 → 6.58）｜脚本 `experiment/scripts/q6_ab.py`｜
原始文本 `/tmp/q6/`｜盲评表 `/tmp/q6/q6_sheet.md`｜预注册 `/tmp/q6/q6_prereg.md`

臂：**A** = plan(LLM) → 3 候选 → 按阻断问题数选 → revise ；**C** = 裸生成一次。
B（仅后编辑）在冒烟阶段即取消，理由见 §1。

## 1. 三处机制在真实模型输出上没有触发（本轮最重要的发现）

| 机制 | 设计意图 | 实测 |
|---|---|---|
| `revise()` 后编辑 | 按审查命中逐句替换 | **A 臂 10 组：applied=0，skipped 合计 1。一次都没改。** |
| 多候选择优（F3） | 3 温度候选按质量选 | **9/10 选 #0**；实测 6 个候选的 `blocking` **全部为 0** |
| 阻断级判据 | 判别机械复用 | 真实输出 issues 1–3 条，最高 severity **0.55** < `min_severity=0.6` |

对照：项目自己的模板拼接样本 `blocking=2`（`experiment/reports/report.md` §1）。
**即：审查器对「模板垃圾」有火力，对「真实模型散文」无话说。** 这正是 `report.md` §3
「AUC=1.0 不是好消息，是样本太容易」的后果，现在在真实样本上兑现了。

机制叠加的后果：A 臂 =「plan 提示词 + 温度 0.75 的单稿」。`min(key=(blocking, candidate_id))`
在 blocking 全为 0 时稳定退化为 `candidate_id=0`，而 `temperatures=[0.75, 0.9, 1.05]`
第一个是最低温——**选稿规则系统性地选最保守的那一稿**。

## 2. 客观指标：A 不如 C（n=10，未做显著性）

| 指标 | A | C | A−C 均值差 | A>C 组数 |
|---|---|---|---|---|
| 字数 | 969.8±88.4 | 1093.1±127.0 | −123.3 | 3/10 |
| 骨架复用率 | **0.410**±0.066 | **0.358**±0.061 | **+0.052** | **7/10** |
| 模式熵 | 6.642±0.152 | 6.819±0.174 | −0.177 | 3/10 |
| 相邻相似度 | 0.499±0.012 | 0.492±0.017 | +0.007 | 4/10 |
| 阻断问题 | 0.1±0.3 | 0.3±0.5 | −0.2 | — |
| issues 数 | 1.9±1.4 | 1.6±0.8 | +0.3 | 5/10 |

方向与本项目主张相反：生成期控制臂的复用率**更高**、熵**更低**、字数**不够**。
但这不能直接读成「生成期控制无效」——它的实现恰好等于「最低温单稿 + 指标提示词」，
见 §1。要回答 Q6，必须先修 §3 的三处，再重跑。

## 3. 修复清单（按优先级）

1. **选稿 tiebreak 不能是 `candidate_id`**。blocking 全 0 时应在平票集合里按
   模式熵最高／复用率最低选，或随机；当前写法把「多候选择优」变成「稳定选最保守」。
2. **审查器阈值在真实输出上无动态范围**。`min_severity=0.6` 高于真实输出最高 0.55，
   导致 revise 永久空转。要么重标阈值，要么承认「后编辑」只对明显劣质稿有效，
   并在产品里把 revise 降级为可选。
3. **`Blocking` 判据需要针对真实模型输出重新设计**——现在的判据只在模板样本上
   标定过，对模型散文的检出率实测为 0。

## 4. 不能从本轮得到的

- 不能说明 A 与 C 的文字**质量**孰优——那是盲评的活，本轮只记录客观指标；
- 不能说生成期控制无效——机制未触发（§1），本轮测的不是 Q6；
- n=10，单项差 0.05，不做显著性、不宣称等价；
- A 臂成本约为 C 臂 4 倍，成本不对等。

## 6. 已修的代码（2026-11-14）

1. src/inksoul/generation.py 选稿改秩：原来 min(key=(blocking, candidate_id)) 在阻断恒为 0 时
   退化成「永远选候选 0」（= 温度 0.75 最保守稿）。现改为
   (blocking, -pattern_entropy, reuse_rate)：平票时取复用最低、熵最高那稿。
2. revise() 的 min_severity 0.6 -> 0.45。真实模型输出的最高 severity 只有 0.55，
   旧阈值使后编辑永久空转（实测 10 组 applied=0）。

## 7. 后续实验（q6b）

弃用「温度造多样性」，改为同温度、只换 user prompt 的一段，三臂各篇只生成一次、不选稿不改稿：

- C 裸生成：只给题材
- P 具体条件：视角／时间窗／禁写项，不含统计指标
- D 统计指标：人类池 p10-p90 目标表（现行规划块）

脚本 experiment/scripts/q6b_conditions.py，5 组 x 3 臂，盲码甲/乙/丙。

## 8. q6b 结果（5 组 x 3 臂，同温度 0.9，各篇只生成一次）

机械指标（n=5/臂）：

| 臂 | 字数 | 骨架复用率 | 模式熵 | 阻断 |
|---|---|---|---|---|
| C 裸生成 | 1326±110 | 0.407±0.050 | 7.117±0.152 | 0.40 |
| P 具体条件 | 1324±126 | 0.386±0.066 | 7.037±0.180 | 0.00 |
| D 统计指标 | 1198±91 | **0.452**±0.043 | **6.958**±0.166 | 0.00 |

D（把人类池 p10-p90 目标表塞进提示词）在**本项目自己的指标上最差**：复用最高、熵最低、
字数最少。C 与 P 接近。

人评（用户盲评）：第 1 组 丙 > 甲 > 乙。揭盲为 C > P > D，与机械指标同向。
前两轮 Q6（地铁组、病房组）用户也都选裸生成版。

累计三点一致：n=3 次人评 + n=15 篇机械指标，均指向「加规则表 -> 更模板化」。
小样本，未做显著性，不作终局结论。
