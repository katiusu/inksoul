| 层 | 选型 | 版本 | 状态 | 备选/升级路径 |

## 2. 三个架构方案：先选哪个

| | **A 全插件** | **B Skill + 脚本** | **C 外部服务** |
|---|---|---|---|
| 形态 | TS 插件注册工具 + Python sidecar | `SKILL.md` + 可执行脚本，人/Agent 手动调用 | 独立 HTTP 服务，插件只做客户端 |
| 首版工作量 | 大（工具契约、生命周期、错误处理） | **小（1/3）** | 中 |
| 能否被 Agent 自动调用 | ✅ 原生 | ⚠️ 靠提示词+手动 | ✅ 但多一跳 |
| 流式改写能力 | ❌ 平台不提供 token 级 hook | ❌ | ❌ |
| 迭代速度 | 慢（改 TS→重载） | **快（改 py→立即生效）** | 中 |
| 分发成本 | 中（打包/版本） | **最低（一个目录）** | 高（要运维） |
| 适合阶段 | v2+ | **v0–v1** | v3（多用户/共享基线） |

**建议：B → A 渐进**。
先用 skill+脚本把**诊断能力本身**验证出来（"这套指标到底能不能区分、能不能指导改写"），确认有效后再包成插件。
理由：整个项目最大的未知不是"插件怎么写"，而是 **Q6——生成期/诊断驱动的控制到底有没有用**。在验证 Q6 之前投入插件工程是**把成本押在未验证的假设上**。
代价：skill 形态下 Agent 的自动调用弱于插件，v0 只做人机协作，不做全自动。

## 3. 开发顺序（v0 → v3）

### v0：最小可跑诊断（目标 5–8 人日）

| 交付 | 验收标准 |
|---|---|
| 小句切分器（标点 + 连接词 + 零句规则） | 在 200 句人工标注集上边界 F1 ≥ 0.85 |
| L1 骨架串提取 + 归一化 N1–N10 | 手工 20 对句子上，同构句对相似度 > 非同构对（人工判可接受） |
| L2 依存边集 + L3 WL 子树核（spaCy） | 5 句烟雾测试通过（已达成：A/B 余弦 0.568、APTED 1） |
| 重复检测（freq≥3 & para_spread≥2 & gap_cv<0.5） | 在自建 5 篇小样本上，人工标注的重复组召回 ≥ 0.6 |
| CLI：`inksoul scan file.md` 输出 JSON | 一条命令给出六类指标，无崩溃 |

**注意**：v0 **不产出任何"AI 味分数"**（见 `agent_architecture.md` ADR-2）。

### v1：基线 + 效度（目标 8–12 人日）★ 最关键

| 交付 | 验收标准 |
|---|---|
| 人类文学基线（5 体裁 × 每体裁 ≥30 篇） | 每体裁的指标分布（均值/分位）可复现 |
| 判别效度实验（人类 vs 多模型生成） | 单指标 AUC ≥ 0.7 的指标至少 3 个；否则回退改指标 |
| **Q6 对照实验**（生成期控制 vs 后编辑） | 预注册；这是**决定项目是否继续**的闸门 |
| 人评协议 v1（≥3 专家、TOST） | κ 达标，评分手册冻结 |

**v1 的闸门规则**：若 Q6 显示"生成期诊断驱动控制"与"直接重写"无差异（TOST 等效），则**项目重心必须转向"诊断工具"而非"生成控制器"**——这是一个预先声明的转向条件，不是失败。

### v2：插件化 + 生成控制器（目标 10–15 人日）

- 把 v0/v1 的算核包成 DSH 插件（工具注册 + 命令 + 配置）；
- 生成控制器的四个控制点（解码配置/候选选择/局部重写/上下文组织）；
- 候选重排：生成 3–5 个候选，按**多指标帕累托**而非加权和选。

### v3：增强（按需）

- LTP 升级（若 torch 到位）；
- DExperts 风格的 anti-expert 解码（需要模型通道与权重）；
- 多语言（先验证中文的哪些指标可迁移，不假设）。

## 4. 成本估算

| 项 | 估计 | 说明 |
|---|---|---|
| v0 | 5–8 人日 | 纯规则+统计，本机可完成 |
| v1 | 8–12 人日 | 含语料清洗与人评组织，**人评是主要成本** |
| v2 | 10–15 人日 | TS 插件工程 |
| 人评 | ≥3 专家 × ≥100 项 × 2 轮 | 按 `evaluation_framework.md` 样本量，**这是最贵的一项** |
| 算力 | **≈0** | 不做训练；诊断全 CPU |
| 语料 | 需授权 | 见 §6 风险 R4 |

**结论**：本项目在小样本阶段的成本瓶颈**不是算力，是标注与人评**。

## 5. 风险矩阵

| # | 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|
| R1 | **Q6 被证伪**（生成期控制不如后编辑） | 中 | **极高（架构重排）** | v1 前置为闸门实验；先做 B 方案不押插件 |
| R2 | 指标不判别（AUC<0.7） | 中 | 高 | v1 设"≤3 个达标指标则回退"的退出条件 |
| R3 | 分词污染指纹 | **高** | 中 | 冻结分词层；指纹记录 `{tokenizer, version}`；换分词即重建基线 |
| R4 | 语料版权 | 中 | 高 | 只发布**统计量**，不发布原文；人类基线用可授权语料 |
| R5 | torch 装不上 | 高 | 中 | 主路径不依赖神经模型；升级为可选 |
| R6 | 文体漂移（模型换代后基线失效） | **高** | 中 | 基线带版本与日期；每季度重测一次判别效度 |
| R7 | 过拟合到"人类平均"，写出平庸文本 | 中 | 高 | 只做**分布约束**不做**均值回归**（`generation_strategy.md` 核心原则） |
| R8 | 过度追求多样性导致生硬 | **高** | 高 | 多样性与生硬度**联立**约束，任一超阈值即拒绝候选 |
| R9 | 人评不可靠（κ 低） | 中 | 高 | 一次性评完 + 校准轮 + TOST；不复用"猜作者"范式 |
| R10 | 中文文学基线缺失导致无参照 | **确定** | 高 | 这是已知缺口，v1 第一件事就是自建 |

## 6. 明确不做

1. **不做 AI 检测器**，不输出"AI 概率"，不针对检测器优化（`literature_review.md` §6）。
2. **不做训练/微调**（本机无 GPU，且训练会引入新的同质化风险）。
3. **不做"一键去 AI 味"按钮**——诊断必须可解释、可拒绝执行。
4. **不做跨语言的统一指标**——中文的零句/流水句结构在英文指标下无意义。
5. **不做自动终判**——LLM 评委与专家的 κ≈0（Chakrabarty 2024），终判必须是人。

## 8. 关键路径与"可推翻点"

```
小句切分 → L1/L2/L3 指纹 → 重复检测 → 基线 → 判别效度 → Q6 对照 → 插件化
    ▲                                    ▲
    └── 若 F1<0.85 则整个指纹失效 ────────┘  若 AUC<0.7 则指标失效
```

**三个可推翻点**（任一触发都要停下来重设计，不许硬推）：
1. 小句切分 F1 < 0.85 → 指纹的地基不成立。
2. 判别效度 < 0.7 → 指标测的不是我们以为的东西。
3. Q6 等效 → 生成控制器无独立价值，转向诊断工具。

这三条写在这里，是为了**在结果不利时不找理由**——本项目的研究目标不是证明初始设计正确（任务书工作原则第 8、10 条）。

## v0.2 候选（2026-11-06 论文比对后新增）

1. **Ω 最优性**：按 Ferrer-i-Cancho 2022 实现 `(D_rla − D) / (D_rla − D_min)`，需要 LAL 库或自写
   Gildea–Temperley；这是 Muñoz-Ortiz 2024 里人类/模型分离最大的一维，目前完全空白。
2. **阈值标定**：`cluster_sim_threshold=0.60`、`corpus.NEAR_IDENTICAL_SIM=0.90`、`mid_share` 分段，
   需 ≥200 对小句 + ≥50 篇机械感判定的人工标注。
3. **中文 Biber 清单**：定语链嵌套（「的」字多层）、动词名词化（「进行…的处理」）、介词框架、
   并列短语堆叠、被动标记（被/受/遭），按体裁分层出基线。
4. **TTCW 中文版 14 条**：Chakrabarty 2024 的二元 rubric 移植，作为外评维度。
5. **真模型语料**：`experiment/gen_model_samples.py`，替换现有模板拼接，重跑跨文本相似度表。
