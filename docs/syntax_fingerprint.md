# 语法指纹（Grammatical Fingerprint）技术设计

> 版本：v1（研究阶段，未实现）
> 要解决的问题：**识别表面词汇不同、但底层句法结构相似的小句**，并判断这种相似是"机械复用"还是"修辞重复"。
> 示例（本项目最小测试对）：
> - A「她没有回答，只是看着窗外。」
> - B「他没有解释，只是低头整理衣袖。」
> 两句话共享 → `代词 + 否定副词 + 动词 + 「，」 + 副词"只是" + 动词短语`

## 0. 六个必答问题（任务书第五节）

先给结论与位置，避免读者在 16k 字里找不到答案。

| 任务书问题 | 直接回答 | 详见 |
|---|---|---|
| 1. 如何提取抽象句法结构？ | **三层并行抽象**：L1 小句骨架串（POS+DEPREL 压成功能槽）、L2 依存边多重集（父-子关系+相对位置）、L3 WL 子树指纹（标签增强子树哈希）。同一份预处理产出三者，按任务取层：线上用 L1，挖掘用 L3 | §1、§2 |
| 2. 如何做句法模式归一化？ | **N1–N10 十条规则**，核心是"内容槽抽象化、功能锚点保留"：人名/地名/机构→`N_*`，具体动词→`V` 但**保留"否定/体标记/副词"**（它们才是模板的指纹）。归一化的取舍标准是：**归一后仍能把 A/B 两例判为同构，但不会把无关句判为同构** | §2 |
| 3. 如何计算结构相似度？ | **主判据：加权编辑距离**（功能锚点替换代价 1.0、内容槽替换 0.15）——因为精确哈希对长度敏感（实测 5 句全不同），等长通配匹配会漏掉真实复用；**辅判据：WL 子树余弦**（实测 A/B=0.568，其余句对 0.25–0.31）；**可解释对照：APTED 树距离**（A/B=1，其余 5–13） | §3、附录 A |
| 4. 如何识别跨段落重复？ | 骨架簇 + **三条件联合**：簇频次 `freq≥3`、段落跨度 `para_spread≥2`、间隔变异 `gap_cv<0.5`。第三个条件的作用是排除"修辞性复现"（有意为之的间隔是有节奏的，机械复用的间隔是随机或过密的） | §5 |
| 5. 如何区分正常修辞重复与机械化复用？ | **J1–J4 四判据**：J1 位置是否固定（句首/段首垄断）、J2 是否跨人物/跨场景无差别使用、J3 是否夹带具体细节（有具体物象=修辞，纯功能槽=模板）、J4 间隔是否有节奏。**四判据不打总分**，任一 fail 记一条可解释证据，交人判断——因为"修辞重复"本身无客观阈值 | §6 |
| 6. 如何建立不同文学体裁的参考分布？ | **双指标 + 体裁内阈值**：`coverage`（生成文本覆盖了该体裁基线的多少骨架）+ `novelty`（有多少骨架不在基线内）；阈值 τ 取**该体裁内部**的 95 分位，而不是跨体裁统一值。依据：Rallapalli 等（2026）实测**体裁效应大于来源效应**，故基线必须按体裁分层 | §7 |

**一条元原则**：本设计的所有参数（`≥3`、`0.5`、`95 分位`）都是**待标定值**，不是结论。标定方法见 `evaluation_framework.md` 实验 1；在标定完成前，任何输出都必须标注"未标定"。

## 0. 设计原则与理论依据

### 0.1 三条硬约束（来自已有实证）

| 约束 | 依据 | 对设计的影响 |
|---|---|---|
| **追求"句法多样性最大化"会伤害质量** | Guo 等（2025）在 5 个任务上测得：**句法多样性与质量分数常呈负相关**（"higher syntactic diversity is associated with lower quality scores"），而词法/语义多样性与质量正相关 | 指纹不能输出"越高越好"的标量奖励；必须是**分布匹配**（离体裁基线多远），不是单调递增 |
| **判别的关键是"覆盖度(recall)"而非"合法性(precision)"** | Guo 等（2025）用依存树 + Weisfeiler-Lehman 核做 precision-recall：模型 precision **99.07–99.73%**（几乎全部落在人类句法支撑集内），recall 仅 **35.20–75.27%** | 检测"AI 式句法"最灵敏的量是**人类句法模式在生成文本中的缺席率**，不是"生成了非法句法"。因此指纹必须以"**人类基线覆盖缺口**"为中心指标 |
| **偏差主要来自指令调优，而非预训练** | Reinhart 等（2025）：Llama 3 base 的特征率几乎贴着人类（\|d\|≤0.25），同族 instruct 偏离显著（present participial clauses d=0.56，名词化 d=0.59），GPT-4o 最大（d=1.38 / 1.23） | 目标基线必须**按模型族与档位分别校准**；不存在"一个人类基线全模型通用"。而且"减"比"加"更划算：GPT-4o 的 participial clauses 是人类 527%，要回到人类率需**削减 60–80%** |

### 0.2 指纹的定义

定义一个语法指纹函数

```
FP(s) = ( S(s), E(s), W(s), M(s) )
```

- `S(s)`：小句骨架序列（POS/DEPREL 抽象串）——用于**精确模板匹配**
- `E(s)`：依存边多重集（父-子 DEPREL + 相对位置）——用于**部分结构匹配**
- `W(s)`：WL 子树指纹集合（标签增强的子树哈希）——用于**核方法与嵌入**
- `M(s)`：映射表（哪些词被归一到哪一类功能槽）——用于**可解释归因**

四者共用同一份预处理（§1），只是抽象层级不同。**分层是刻意的**：L1 便宜、可解释、适合线上；L3 昂贵、能捕捉"结构同构但标签不同"的相似，适合离线挖掘。

## 1. 预处理：把汉语文本变成"可比对的骨架"

这是整个方案最容易失败的地方——90% 的误差来自预处理，不是来自相似度算法。

### 1.1 小句切分（必须先做，理由见 `linguistic_analysis.md` §4.1）

汉语书写句常含多个小句。若不切分，依存解析器会把多小句强制挂成一棵单根树，产生假边（把第二小句谓语挂到第一小句宾语上）。

切分规则（按优先级）：

1. **标点边界**：`，` `；` `：` `、`（顿号在并列 NP 内不算小句边界，需前看是否为谓词）、`。` `？` `！` `……` `——`。
2. **句末标点必切**，`,` `；` 默认切，但以下**不切**：
   - 引语标记前后（`说："……"`）
   - 数字/日期内的逗号
   - 插入语（`他，据我所知，已经走了`）——用括号/破折号配对识别
3. **连词前切**：`然后/于是/但是/可是/因为/所以/如果/虽然/而/却/只是` 等出现在小句首时，作为新小句起点（连词归属新小句）。
4. **合并规则**：切完后若某片段无谓词且长度 <4 字，并入相邻小句（避免"的"字短语被切成独立片段）。

```python
CLAUSE_DELIM = set("，；：？！。…—")
NO_SPLIT_BEFORE = set("的说吗呢吧啊呀")
CONJ_HEAD = ["然后","于是","但是","可是","不过","因为","所以","如果","虽然",
             "而","却","只是","就","便","也","还","又"]
```

### 1.2 零主语还原（ZERO→TOPIC）

汉语话题链允许主语持续省略。若不还原，骨架会呈现"无主语畸形树"，模板统计失真。

算法（贪心话题链，O(n)）：

```
对每个小句 c_i（i>1）:
  若 c_i 的解析结果没有 nsubj（或只有标点）:
     找最近的前向小句 c_j (j<i)，取它的 nsubj / 或它的 obj 若该 obj 在 c_i 中未出现
     若距离 ≤3 小句 且 中间无新话题候选 → 打标记 ZERO→TOPIC(j)
     否则 → 打标记 ZERO→UNRESOLVED
```

- 还原后的骨架里保留 `ZERO` 作为显式符号（**不**填回具体词），这样"零主语连续"本身成为一个可统计的结构特征——这恰恰是汉语叙事的核心节奏标记。
- `ZERO→UNRESOLVED` 比例是**语篇连贯度的诊断量**，本身值得上报。

### 1.3 词汇归一：把"内容词"和"功能骨架"分开

指纹的目标是"结构"，因此**内容词必须被抹掉，功能词必须被保留并分类**。归一映射表（初版，需按语料迭代）：

| 原词类 | 归一标签 | 示例 |
|---|---|---|
| 人称代词 | `PRON` | 他/她/它/我/你/他们 |
| 指人专名 | `NAME` | 张三/老王 |
| 普通名词 | `N` | 衣袖/窗外/桌面 |
| 动词 | `V` | 回答/解释/整理 |
| 形容词 | `A` | 慌乱/沉重 |
| 程度副词 | `ADV_DEG` | 很/太/非常/极 |
| 范围/限定副词 | `ADV_LIM` | 只是/仅仅/只/不过 |
| 否定副词 | `NEG` | 不/没/没有/别 |
| 时间副词 | `ADV_TIME` | 已经/刚刚/忽然/终于 |
| 情态副词 | `ADV_MOD` | 大概/也许/似乎/仿佛 |
| 介词 | `PREP_<sub>` | 把→`PREP_BA`、被/让/叫/给→`PREP_BEI`、在→`PREP_LOC` |
| 体标记 | `ASP` | 着/了/过 |
| 结构助词 | `DE` | 的/地/得（分别 `DE_N`/`DE_ADV`/`DE_COMP`） |
| 语气词 | `PART` | 呢/吧/啊/罢了 |
| 连词 | `CONJ_<sub>` | 因为→`CONJ_CAUSE`、但是→`CONJ_CONTRAST`、只是→`CONJ_LIMIT` |
| 数词/量词 | `NUM` / `CL` | 一/两/个/条 |
| 标点 | 保留原符号 | ，。？！ |

**关键设计**：`只是` 在不同语境可能是副词（`只是看着`）或连词/转折标记（`只是他没说`）。必须在归一前用依存标签消歧：`advmod` → `ADV_LIM`；`cc`/`mark` → `CONJ_LIMIT`。**这是"模板"误判的高发点**——A/B 两例里 `只是` 都是 advmod，属同模板；若一句是 cc 则不应判同模板。

### 1.4 语序归一 vs 语序保留

- **L1 骨架序列**：保留线性语序（这是汉语意合的关键，`把` 字句的语序就是语义）。
- **L2 依存边集**：语序以"相对位置"编码（父在子前/后），而不是绝对位置。
- **L3 WL 子树**：天然无线性序，只有树结构——因此 L3 会把"语序不同但结构同构"的句子判为相似。**这是特性也是风险**，见 §7 局限。

## 2. 三层表示

### L1：小句骨架串（cheap, interpretable）

```
FP_L1(c) = [ norm(w) for w in c.tokens ]
例 A: PRON NEG V ， CONJ_LIM V PREP_LOC N
例 B: PRON NEG V ， CONJ_LIM V N N
```

匹配方式：**带通配的模式匹配**。`N`/`V`/`A`/`NAME` 视为通配符，功能类（`NEG`/`ADV_LIM`/`CONJ_*`/`PREP_*`/`DE`/`ASP`）视为必须精确匹配的**骨架锚点**。

这样 A 与 B 的匹配串都是 `PRON NEG V ， ADV_LIM V *`——**骨架完全一致**，且锚点是功能词，不会因为"看窗外"vs"整理衣袖"而被破坏。这就是 §0 示例的形式化。

L1 复用率 = 骨架串在文档内的出现次数 / 小句数。

> 注意：L1 对长度敏感（`*` 只能吸收内容词）。因此需要"骨架串 + 长度分箱"两级统计。

### L2：依存边集（medium）

```
FP_L2(c) = { (deprel, child_pos_class, parent_pos_class, dir) }
dir = +1 表示父在子前，-1 表示父在子后
```

A 的边集：
```
(nsubj, PRON, V, +1)   (neg, NEG, V, +1)   (advmod, ADV_LIM, V, +1)
(xcomp|conj, V, V, +1) (obl, N, V, +1)     (case, PREP_LOC, N, +1)
```
B 的边集：
```
(nsubj, PRON, V, +1)   (neg, NEG, V, +1)   (advmod, ADV_LIM, V, +1)
(xcomp|conj, V, V, +1) (obj, N, V, +1)     (compound|amod, N, N, +1)
```
**差异只在最后一两条边**。因此 L2 相似度天然比 L1 更"宽容"，能抓住 L1 抓不到的近邻结构。

相似度：Jaccard / 加权 Jaccard（`neg`/`advmod`/`conj`/`cc`/`mark`/`xcomp` 权重高）。

### L3：WL 子树指纹 + 核距离（expensive, expressive）

直接采用 Guo 等（2025）验证过的路线：依存树 + 节点标签（POS + 归一后的功能类）+ Weisfeiler-Lehman 子树核。

WL 迭代：
```
h_0(v) = label(v)                        # POS + 归一功能类 + 句法角色
h_{i+1}(v) = HASH( h_i(v), multiset{ h_i(u) : u ∈ N(v) } )
```
每轮迭代产生一个"半径 i 的子树指纹"哈希。把每个小句表示为子树指纹的多重集（可加 deprel 到边上）。

**距离**：两个方式
1. **核**：`K(t1,t2) = <φ(t1), φ(t2)>`，φ 为指纹计数向量 → 归一化 `K/√(K11·K22)`，距离 = 1 − 相似度。复杂度与指纹总数线性，可先做哈希 + 稀疏向量。
2. **嵌入**：对全语料的小句算 φ，PCA/t-SNE 降维，或直接用 KMeans 聚类（Guo 用 GPT-2 嵌入 + PCA + KMeans 估计支撑集，本文用小句自身的 WL 指纹嵌入即可，无需外部模型——**更可控、无外部依赖**）。

> 为什么不用预训练句向量？因为预训练嵌入是**语义**空间，会把"看窗外"和"整理衣袖"拉开得很远，恰好破坏我们想找的"结构相似"。WL 指纹只看到结构，这才是"语法指纹"该有的性质。

## 3. 相似度计算：三种距离与它们各自的失败模式

| 方法 | 定义 | 成本 | 擅长 | 失败模式 |
|---|---|---|---|---|
| **TED（树编辑距离）** | 最小编辑操作数 | O(n²)~O(n³) 每对；Zhang & Shasha 算法对无序树精确，有序树更便宜 | 结构近乎同构时的精确度量 | 慢；对"加一个修饰语"惩罚过重；汉语长句树大，批量不可行 |
| **WL 核距离** | 1 − 归一化核 | O(n) 每对（稀疏向量点积） | 批量、可扩展、对局部同构敏感 | 丢掉语序；半径越大越像"全局词袋"，区分度下降 |
| **POS/DEPREL n-gram 余弦** | 骨架串的 n-gram 向量 | O(n) | 极快、可解释、无需解析质量完美 | 对"骨架相同但内容不同"灵敏度低（因为 n-gram 已经把内容词归一了，实际上灵敏度足够，见附录实测） |

**推荐组合**（工程上按"便宜的先跑"）：
1. 线上/实时：L1 骨架串哈希 + 精确匹配 → 直接给"模板复用率"；近邻检索用 L2 Jaccard 在 top-k 候选内算。
2. 离线分析：L3 WL 核 + 聚类 → 给"结构簇分布"，用于精度/召回分析。
3. TED 只用于**小规模精确诊断**（例如"这两句话到底差在哪"，给作者看 diff）。

## 4. 结构归一化的十个汉语专项规则

不归一，"结构相似"会被表层差异淹没。以下规则按"影响最大"排序，每条给出理由。

| # | 规则 | 归一动作 | 理由 |
|---|---|---|---|
| N1 | 否定式多样 | `没/没有/不/别/未` → 统一 `NEG` | 汉语否定词的选择有语体制约（"没"用于已然，"不"用于意愿），但**结构功能相同** |
| N2 | 限定副词家族 | `只/只是/仅仅/不过/就/才` → `ADV_LIM`（若为 advmod） | A/B 例的核心锚点。这些是同一结构槽的不同填充 |
| N3 | 把/被句 | `把 → PREP_BA`，`被/让/叫/给 → PREP_BEI`，但**保留原词类别为子标签** | `把` 与 `被` 结构功能不同（处置 vs 被动），不能合并；但同族内部（让/叫/给）应合并 |
| N4 | 体标记合并 | `着/了/过/起来/下去` → `ASP`（子类保留） | 体标记是骨架级信息，但具体形式受动词情状影响 |
| N5 | `的/地/得` 三分 | → `DE_N`/`DE_ADV`/`DE_COMP` | 三者结构与语体含义完全不同，**不能合并**（合并会抹掉"的地得"文体信号） |
| N6 | 数量短语 | `NUM + CL` → `QUANT` | "一抹""一丝""一缕"是 AI 高频量词，量词本身应单独统计，但在**骨架层**可折叠 |
| N7 | 趋向补语 | `起来/下来/出去/上来` → `DIR` | 趋向补语是汉语特有的动词后成分，若不归一，动词短语结构会被切碎 |
| N8 | 连词语义类 | 按语义映射（cause/contrast/condition/additive/temporal） | 汉语连词数量多但语义类少；按类归一才能比较"形合密度" |
| N9 | 四字格 | 整体作为 `IDIOM` 一个 token | 四字成语内部结构不应被解析进骨架，否则"成语"会伪装成复杂结构 |
| N10 | 引语 | `说/道/问/答 + 「」` → `SPEECH_VERB + QUOTE` | 对话结构是叙事骨架的重要维度，需单独成一类 |

**归一表的维护**：这是一份**数据资产**，需要版本化（`norm_table.v1.yaml`），且每个规则要有单元测试用例（至少 5 对正例/负例）。归一规则错了，后面所有指标全错，且错得"看起来很正常"。

## 5. 跨段落重复检测

单句判重没有意义（人类也会用同一句式两次）。真正的问题是**分布**：同一结构在一篇作品里出现的间隔与频率是否异常。

### 5.1 算法

```
输入：小句骨架序列 [(clause_id, para_id, pos, fp)]
1) 对每个骨架串做精确匹配分组（L1）
2) 对每组内的小句对，用 L2 Jaccard 过滤（≥0.6 才算同簇）
3) 用并查集合并成"结构簇"
4) 对每个簇计算：
   - 频次 freq
   - 覆盖的段落数 para_spread
   - 段落内最大连续出现数 run
   - 平均间距 mean_gap（以小句计）
   - 间距的变异系数 gap_cv
5) 输出"机械复用嫌疑簇"：freq ≥ 3 且 para_spread ≥ 2 且 gap_cv < 0.5
   （频率高、跨段分布、间隔高度规律 → 机械）
```

**为什么用 gap_cv 而不只是频率**：机械复用的特征是**节奏性**（每隔一段就来一次，像模板填槽）；修辞性重复（如段落首句反复）往往**集中在同一位置**（gap_cv 高或 run=0 但有规律的位置槽）。这两个信号必须分开统计。

### 5.2 跨作品重复（同质化检测）

同一骨架在**不同作品**中高频出现 → 群体层同质化（对应 Sourati 等 2026 的"语言景观收缩"）。实现：把骨架串加语料 ID，统计"出现在多少部作品中"。指标：`作品覆盖数 / 总作品数`。这是**最有说服力的 AI 文风证据**（单作品内可能是作者风格，跨作品同骨架才是共性问题）。

## 6. 修辞重复 vs 机械复用：可执行判据

这是本模块最容易被滥用的地方。给出**四条可操作判据**，并要求至少满足 2 条才标记（且输出的是"嫌疑"而非"判定"）：

| 判据 | 可计算量 | 判为修辞性重复的条件 | 判为机械复用的条件 |
|---|---|---|---|
| **J1 位置规约** | 该骨架在段落中的相对位置分布 | 位置高度固定（如总在段首/句末）→ 排比、首句呼应 | 位置随机且均匀 → 模板填空 |
| **J2 变异度** | 同簇内骨架串的编辑距离方差 | 变异大（同一节奏、不同措辞）→ 反复 | 变异极小（几乎逐字结构相同，只换内容词）→ 模板 |
| **J3 功能标记** | 是否存在显式修辞标记（"如同/仿佛/一遍又一遍/……"）或结构标记（三项以上并列） | 有标记 → 修辞 | 无标记且出现在情绪描写位置 → 机械 |
| **J4 上下文必要性** | 去掉该小句后，前后句的语义/句法是否仍然成立（可用删句后困惑度变化代理） | 删掉后断裂 → 必要（修辞承担功能） | 删掉后完全通顺 → 可替换的填充物 |

J4 是最有语言学根据的判据（"重复是否承担不可替代的功能"），但计算最贵（需要语言模型）。工程上：J1–J3 做初筛，J4 只对初筛出的 top-N 嫌疑做精算。

**重要的诚实声明**：这四条判据**尚未在真实语料上验证区分度**。它目前是"设计假设"，必须按 `evaluation_framework.md` 的协议做标注一致性实验（至少 3 名标注者、κ ≥ 0.6 才可用）。**如果 κ 不达标，本模块只能作为 writer 的提示工具，不能作为评分器。**

## 7. 体裁参考分布（从"绝对阈值"转向"分布匹配"）

### 7.1 为什么不能用绝对阈值

Reinhart 等（2025）最关键的结论之一是"LLM 不随语域调节风格"：同一模型在 6 个体裁/语域上的偏离模式一致，而人类在体裁间差异巨大。因此任何全局阈值都会在某些体裁上误判。正确做法：

```
对每个体裁 g，构造人类参考分布 D_g = { φ(t) : t ∈ 人类语料_g }
对新文本 x 的每个小句 t：
  d(t) = min_{t' ∈ D_g} WL距离(t, t')
  或更稳健：d(t) = 到 D_g 的 k-最近邻平均距离
指标：
  coverage(x, g) = 满足 d(t) ≤ τ_g 的小句比例      # 对应 Guo 的 recall
  novelty(x, g)  = 满足 d(t) > τ_g 的小句比例      # 结构新颖度（可能是好事也可能是坏事）
```

τ_g 取 D_g 内部到自身 k 近邻距离的 95 分位（leave-one-out），这样 τ 是体裁自适应的。

### 7.2 双指标：覆盖率与新颖度都要报

- **覆盖率低** → 句法只在人类分布的一小块里打转（Guo 的 recall 现象）。
- **覆盖率过高** → 可能是抄袭式模仿，也可能只是体裁规整。
- **新颖度高** → 可能是创新，也可能是生硬（见 §8）。

**绝不把两者合成单一分数。** 合成就等于把"文学判断"偷偷塞进一个数字里。

## 8. 生硬表达的检测（防止"多样性控制"变成"故意别扭"）

Guo 等（2025）已给出反例式的警示：句法多样性与质量负相关；且他们发现模型**过量**的具体 POS 模板之一就是 `(PRON, NOUN, ADJ)`——如 "her voice soft"，即**无动词小句/独立主格**。这类结构"多样"但常显生硬。

汉语的对应风险点：
1. **强行拆短**：把流水句切成电报体（"他推门。屋里没人。桌上杯子。"）——是小句数暴增但节奏单调。
2. **强行加长**：从句套叠到无法断句（"虽然他很清楚那个在当时看来几乎不可能完成的任务之所以困难的原因在于……"）。
3. **非常规语序**：为求新颖而把状语后置、宾语前置，产生翻译腔。
4. **罕见句式滥用**：突然大量使用名词谓语句、文言残留。

判据：
- `小句长度熵` 与 `句长熵` 必须**同时**高于阈值（只高一个 = 强行拆/合）
- 依存树的**最大深度**与**平均深度**比值（过深 = 套叠）
- 语序偏离度：与同体裁人类语料的"依存方向 n-gram"分布做 KL 散度

## 9. 工程实现（可运行骨架）

```python
# fingerprint.py  (设计稿，依赖见 technical_roadmap.md)
from dataclasses import dataclass
from typing import List, Dict, Tuple
import hashlib, collections

NORM = {
    "不":"NEG","没":"NEG","没有":"NEG","别":"NEG","未":"NEG",
    "只":"ADV_LIM","只是":"ADV_LIM","仅仅":"ADV_LIM","不过":"ADV_LIM",
    "把":"PREP_BA","被":"PREP_BEI","让":"PREP_BEI","叫":"PREP_BEI",
    "着":"ASP","了":"ASP","过":"ASP",
    "的":"DE_N","地":"DE_ADV","得":"DE_COMP",
}
FUNC_ANCHOR = {"NEG","ADV_LIM","PREP_BA","PREP_BEI","CONJ_CAUSE","CONJ_CONTRAST",
               "CONJ_LIMIT","DE_N","DE_ADV","DE_COMP","ASP","PART"}

@dataclass
class Clause:
    text: str
    pos: List[str]          # 词性
    head: List[int]         # 依存父节点索引
    deprel: List[str]       # 依存关系

def norm_token(w, pos, deprel) -> str:
    if w in NORM:
        # 「只是」歧义消解
        if w == "只是" and deprel in ("cc","mark"): return "CONJ_LIMIT"
        return NORM[w]
    if pos.startswith("PN"): return "PRON"
    if pos.startswith("NR"): return "NAME"
    if pos.startswith("N"):  return "N"
    if pos.startswith("V"):  return "V"
    if pos.startswith("A"):  return "A"
    if pos.startswith("M"):  return "QUANT"
    if pos.startswith("C"):  return "CONJ"
    return "OTHER"

def fp_l1(c: Clause) -> str:
    return " ".join(norm_token(w,p,d) for w,p,d in zip(c.text,c.pos,c.deprel))

def fp_l2(c: Clause) -> frozenset:
    edges = set()
    for i,(h,d) in enumerate(zip(c.head,c.deprel)):
        if h < 0 or h == i: continue
        cp = norm_token(c.text[i], c.pos[i], d)
        pp = norm_token(c.text[h], c.pos[h], c.deprel[h])
        d_ = 1 if h < i else -1
        edges.add((d, cp if cp in FUNC_ANCHOR else cp[0], pp[0], d_))
    return frozenset(edges)

def skeleton_match(a: str, b: str) -> bool:
    """L1 骨架匹配：功能锚点必须相等，内容类可通配"""
    ta, tb = a.split(), b.split()
    if len(ta) != len(tb): return False
    for x,y in zip(ta,tb):
        if x in FUNC_ANCHOR or y in FUNC_ANCHOR:
            if x != y: return False
        # 否则视为内容槽，允许不同
    return True
```

**验证方式**（在 `evaluation_framework.md` 的实验 1 中执行）：用构造的 40 对小句（20 对同骨架、20 对非同骨架，人工标注），测 L1/L2/L3 的准确率与召回率。**这一步必须先做，且必须诚实报告**——如果 40 对里 L1 只对 60%，方案就要重设计。

## 10. 计算成本（按 10 万字长篇估算）

| 步骤 | 单位成本 | 10 万字总量 | 说明 |
|---|---|---|---|
| 分词+POS+依存 | 约 1–2 s/千字（LTP/HanLP，CPU） | 2–4 分钟 | 可缓存，一次性 |
| 小句切分 + 零主语 | <0.01 s/小句 | 秒级 | 规则，很快 |
| L1 骨架匹配 | O(n) 哈希 | <1 s | 全文档 |
| L2 Jaccard 对 | O(k²) 内 top-k | 秒级（k=200） | 需倒排索引 |
| L3 WL 核 | O(小句数 × 指纹数) | 小句 ~2 万 → 约 10–60 s（Python+NumPy） | 可离线/异步 |
| 体裁最近邻 | O(n·m) | 需预建索引（faiss/稀疏） | 参考库越大越慢，需分体裁索引 |

**结论**：在线迭代（生成—审查循环）只能跑 L1+L2；L3 与体裁覆盖度应作为**段落级异步任务**，不阻塞生成。

## 11. 局限（必须写进产品文档）

1. **依赖解析质量**：中文依存解析在文学文本（长句、省略、诗性倒装）上错误率高于新闻。所有指标都继承解析误差。**建议**：对高价值段落人工抽检 20 句，报告解析错误率，作为指标的置信区间来源。
2. **WL 丢语序**：L3 对"结构同构但语序不同"的句子判为相似。汉语语序有语义功能，这是系统性偏差。缓解：WL 指纹里加入"子节点相对位置"作为边标签（本设计已加，但会削弱泛化）。
3. **相似 ≠ 机械**：本模块只回答"结构是否重复"，不回答"是否应该重复"。判定必须交给 §6 的判据 + 人工。
4. **跨语言不可直接迁移**：本设计的中文规则（N1–N10）不适用于英语；多语言支持需各自建归一表（`technical_roadmap.md` §多语言）。
5. **未验证**：§6 的判据、§8 的阈值、§7 的 τ 都还没在真实语料上标定。**目前应视为"待验证的设计参数"**。

## 附录 A：L1 骨架的实测验证（n=10，烟雾测试，非证据）

### A.1 为什么先做这个

设计再好，如果"表面词汇不同、句法结构相同"的两句话在实现上被判为不同，整个模块就是空的。因此在写任何架构文档之前先跑了最小验证。脚本：`research/demo_fp.py`；依赖：`jieba`（本机已装，唯一可用的中文工具，见附录 B）。

### A.2 一处设计修正（实测推翻原设计）

原设计（§2 L1）用**等长骨架串 + 通配匹配**。实测第一对就失败：

```
A: 她/没有/回答 ， 只是/看着/窗外     →  PRON NEG V ， ADV_LIM V OTHER 。
B: 他/没有/解释 ， 只是/低头/整理/衣袖  →  PRON NEG V ， ADV_LIM N N N 。
```

B 比 A 多一个内容槽（"低头"与"整理"是两个动词性成分），等长匹配直接判不同。**修正**：改用**加权编辑距离**（sequence alignment），替换代价按"是否功能锚点"分级：

```python
def sub_cost(a, b):
    if a == b: return 0.0
    if a in ANCHOR or b in ANCHOR: return 1.0     # 功能锚点不容错（NEG/ADV_LIM/PREP_BA/...）
    if a in PUNCT or b in PUNCT:  return 1.0
    return 0.15                                    # 内容槽近似等价

sim = 1 - weighted_edit_distance(a, b) / max(len(a), len(b))
```

这条修正的实质是：**"结构相同"不应要求"槽位数量相同"**。人写 A 用三个槽，写 B 用四个槽，骨架仍然同族。这是设计层面的实质变化，不是参数调整。

### A.3 结果（阈值 0.75）

| 组 | 对数 | 正确 | 说明 |
|---|---|---|---|
| 同骨架（人工构造） | 5 | 5 | 相似度 0.764–0.973 |
| 不同骨架（人工构造） | 5 | 5 | 相似度 0.414–0.623 |
| **合计** | **10** | **10** | 烟雾测试通过 |

A/B 原始对：相似度 **0.856**（阈值 0.75 → 判为同骨架 ✓）；对照的错配对：**0.455**（判为不同 ✓）。阈值 0.75 与两簇的间隙（0.623 ↔ 0.764）都还比较宽，说明 L1 在**极端构造**下可分。

### A.4 必须同时报告的负面结果（比上面的 10/10 更重要）

1. **jieba 的词性标注质量不足以支撑本模块**：
   - `低头` 被标为 `n`（应为动词性成分）
   - `整理` 被标为 `n`
   - `窗外` 被标为 `OTHER`（方位/处所名词未覆盖）
   - 结果：B 的骨架被压成 `ADV_LIM N N N`，功能上把一个动词短语链变成名词堆。
   → **结论：L1 在 jieba 上"能跑"，但不能用**。要么换 LTP/HanLP，要么接受"骨架只在名词/动词大类上粗糙可用"。这一条直接决定 `technical_roadmap.md` 的选型。
2. **n=10、由本项目自己构造、且构造时已经知道要测什么**。100% 不构成任何证据，只能说明"实现没写错得离谱"。真正的验证必须是**盲抽的真实文学文本 + 独立标注**（`evaluation_framework.md` 实验 1）。
3. **L2 未验证；L3 只有 5 句的烟雾测试**（见附录 B）：WL 核与 APTED 在 A/B 对上表现正常，但跨段落聚类、体裁最近邻、τ 标定**全部未验证**——仍是设计，不是结果。
