# 从零开始的自然文学生成策略

> 版本：v1（研究阶段）
> 上游：`literature_review.md`（证据）、`linguistic_analysis.md`（问题分类）、`syntax_fingerprint.md`（测量工具）
> 本文回答一个问题：**在不训练、不微调模型的前提下（dsh 插件的能力边界），从第一句话开始，怎么让生成走文学的路而不是走"最可能的措辞"的路。**

---

## 0. 先说结论（三条，都可被证据支持，也都可能被推翻）

### 结论 1：**Prompt 层解决不了这个问题，这不是推测，是实测**

两条独立证据：

1. **Guo 等（2025, TACL）**在 5 个任务上做了 prompt 消融：给提示加 "be as creative as possible"，对词法/句法/语义三个维度的多样性**几乎无影响**，原文结论是"enhancing linguistic diversity through straightforward prompt engineering alone would be challenging"。
2. **Rallapalli 等（2026）**用 11 个模型 × 8 个体裁 × 4 种解码策略做 Biber 特征分析，发现人/机之间的**关键句法差异对生成条件稳健**：让模型"写得更像人"、或直接给它人类文本让它续写，差异**依然存在**；且**体裁效应大于来源（人类 vs 模型）效应**。

再叠加 Reinhart 等（2025）的发现——差异在 Llama base 上几乎为零（|d|≤0.25）、在 instruct 上显著（present participial clauses d=0.56、名词化 d=0.59）、GPT-4o 最大（d=1.38/1.23）——可以得出一个有方向的判断：

> **机械化表达不是"用词偏好"，而是后训练形成的一种生成体制；它作用在结构选择层，不在词汇层，因此不能被措辞级指令抵消。**

**本项目由此推翻最初设想的一条**：不做"更强的风格 Prompt"。Prompt 只用于**设定目标**（写什么、以什么立场写），不承担**控制结构**的职责。

### 结论 2：要控的不是"均值"，是"方差"

这条是本文最重要的技术判断，也是最反直觉的一条。

**Narrative Flattening（Li 等 2026）**给了决定性的数字。他们用同一架构/规模/分词器/预训练的 OLMo-32B 四个 checkpoint（Base / SFT / DPO / RLVR）做匹配续写：

| 阶段 | 主题跳转的篇内 CV | 相对人类 |
|---|---|---|
| 人类（New Yorker） | 0.105 | — |
| Base | 0.096 | −8.0% |
| SFT | 0.089 | −15.1% |
| DPO/RLVR | 0.081 | −22.2% |

（混合效应模型：β = −0.0228，95% CI [−0.0234, −0.0222]，p < .001）

**关键在于作者补的那句话**：这不是"动得更慢"——RLVR 的**相邻句平均距离反而略大于人类**（1.167 vs 1.133）；**掉下去的是跳转幅度的标准差**（0.095 vs 0.117）。

同理，**Sourati 等（2026, Nat. Hum. Behav.）**发现 LLM 润色会让写作复杂度的方差下降 **21–50%（p≤.05）**，而语义余弦在 87% 的样本上 >0.95——**内容几乎没变，变的是风格的离散度**。

这两条合起来给出了本项目的核心优化目标：

> **不是"让每一句都更新颖"，而是"让整篇的句法/节奏选择重新获得人类作品那样的离散度"。** 前者会导致句句用力（生硬），后者才是文学的自然起伏。

**这条结论直接解释了"为什么不能简单提高多样性"**：Guo 等（2025）测得**句法多样性与质量分数常呈负相关**。若按"越多样越好"优化，等于系统性牺牲质量。正确的目标是**分布匹配**（把方差拉回体裁参考区间），不是**极值最大化**。

### 结论 3：控制点只有四个，且都在"生成之外"或"生成之间"

dsh 插件不能训练、不能流式改写模型输出（无 token 级 hook，见 `agent_architecture.md` §2.3）。因此可行的控制面被压缩为四个：

| # | 控制点 | 手段 | 证据 |
|---|---|---|---|
| C1 | **解码配置** | temperature / top-p / 多候选数 | Guo：温度↑词法多样性↑、质量仅轻微下降，t=0.6 是甜点；温度对句法多样性影响不稳定。Bellemare-Pepin 等（2026）：T=1.5 时 GPT-4 的发散联想均值 85.6，超过 72% 的人类，但默认温度下低于人类上半区 → **配置本身就能移动天花板** |
| C2 | **候选选择** | 生成 k 个候选，用结构评分重排 | Diverse Beam Search（Vijayakumar 等 2016）：加多样性惩罚后**top-1 质量反而能变好**，说明"多样 vs 质量"不是硬权衡 |
| C3 | **局部重写** | 只改结构违规的小句对 | 最小编辑原则；避免整段重写带来的连贯损失（§4.3） |
| C4 | **上下文组织** | 把"已用结构/人物语言卡/信息释放表"作为动态上下文注入 | Rallapalli：体裁效应 > 来源效应 → **上下文里放对体裁样本，比放"你要像人一样写"更有效** |

C1/C2/C3 是"生成之外"，C4 是"生成之间"。**没有任何一个是"生成之中"**——这是插件架构的硬约束，也是本设计的诚实边界。

## 1. 六种生成策略的系统比较（用户指定要比较的六种）

评分说明：★★★ = 本项目采纳为主路径；★★ = 采纳为辅助；★ = 不采纳。

| 策略 | 机制 | 证据强度 | 效果（对 P1–P9） | 成本 | 局限 | 取舍 |
|---|---|---|---|---|---|---|
| **S1 普通 Prompt** | 一次性指令出全文 | 强（大量反例） | 极弱：Reinhart/Guo/Rallapalli 三方一致显示措辞指令不改结构 | 最低 | 无法控制结构；长度一长必然塌回默认节奏 | ★ 只保留为"内容指令"通道 |
| **S2 Few-shot 风格条件** | 给若干人类样例 | 中 | 中：能改**体裁**方向（Rallapalli 显示体裁效应最强），但改不了"是否模板化" | 低（占上下文） | 样例选择偏差大；样例本身可能被模仿到"抄袭级"相似；中文长样例极吃上下文 | ★★ 用**短样例 + 多体裁**，每段 2–3 句，不整篇 |
| **S3 结构化规划** | 先生成大纲/场景表/信息释放表，再逐段写 | 中—强（计划式生成路线，本文档不锁定单一出处；dsh 插件可承载） | 强：直接压制 P6（过度解释）、P4（节奏单一）；间接改善 P2 | 中（多一次模型调用） | 规划本身也可能模板化（"起承转合"套话）；规划与正文易脱节 | ★★★ **主路径**：规划产物必须是**可检查的表**（见 §3 L1） |
| **S4 句法多样性控制** | 显式约束句式/骨架分布 | 中：Guo 给出度量与 precision/recall 范式；Shaib 给出模板可追溯性 | 中—强：**唯一直接针对 P2 的手段** | 中—高（需解析 + 候选重排） | 解析误差；过度约束→生硬（Guo：句法多样性与质量负相关） | ★★★ 但**只做重排与局部重写**，不做硬性禁止 |
| **S5 迭代生成 + 审查** | 生成→审查→重写循环 | 中 | 强（长期），但**单轮收益递减** | 高（token 成本 × 轮数） | 多轮会**向均值回归**（每轮都在"改得更安全"）；可能越改越平 | ★★ 限 1–2 轮，且审查只看**结构指标**，不看"像不像 AI" |
| **S6 上下文感知生成** | 把人物状态/前文骨架/信息释放表注入 | 中 | 中—强：改善 P7（人物声音）、P6（信息释放） | 低 | 上下文污染（模型会把注入的指令当内容写出来） | ★★★ 用于**状态**，不用于**风格形容** |

### 1.1 为什么 S5（迭代审查）要限轮数——一个反直觉的机制

迭代审查的自然实现是"发现 AI 味 → 让模型改得更自然"。但这里有一个系统性风险：**每次"修改"都倾向于向更安全、更常见的表达收敛**（这与 Sourati 等观察到的"润色使方差下降 21–50%"是同一现象）。也就是说：

> **迭代审查可能不是在"去机械化"，而是在"用另一种机械化覆盖前一种"。**

因此本项目的规则是：**审查只能针对"可测量的结构偏差"提出具体改法，禁止使用"让它读起来更自然"这类模糊指令**。模糊指令 = 让模型自己决定什么叫自然 = 回到高概率路径。

## 2. 为什么"提高多样性"会失败：三种已知的失败模式

| 失败模式 | 表现 | 机制 | 防范 |
|---|---|---|---|
| **F1 句句用力** | 每句都想奇崛，读起来做作 | 局部最优叠加；句间没有功能分工 | 只在**配额不足**时触发重排；大多数句子应落在基线内（宁可平庸，不要通篇用力） |
| **F2 强行拆/合** | 电报体 或 从句套叠 | 只优化了"句长方差"这一个量 | 同时约束**小句长度熵**与**依存深度**（`syntax_fingerprint.md` §8） |
| **F3 语义漂移** | 结构改了，但指代/事实/情绪断裂 | 重写时丢失上下文约束 | 局部重写必须带"前后各 2 句 + 人物卡"作为锚；改完做一致性检查 |

另有一条外部证据值得记住：**Bellemare-Pepin 等（2026）**发现 GPT-4 在 10 万人规模的 DAT 基准上、T=1.5 时均值 85.6、超过 72% 的人类，但**默认温度下低于人类上半区**，且 GPT-4-turbo 相对 GPT-4 **退步**了；同时 70% 的答卷里出现了 "microscope"。→ **"高多样性配置"会带来词汇塌缩（同一批高频词反复出现）**。多样性指标与词汇新颖度是两个方向，必须同时监控。

## 3. 五层生成流水线（InkSoul 的实际答案）

```
L0 状态层   ：世界/人物/伏笔/时间线（结构化 JSON，持久化）
L1 规划层   ：场景卡 + 信息释放表 + 节奏曲线（每场景一张，可检查）
L2 配额层   ：本段落的结构预算（分布目标，不是禁止清单）
L3 生成层   ：逐段落生成 k 个候选（k=3）
L4 修整层   ：结构评分 → 选优 → 局部重写（≤2 轮）
L5 审查层   ：文学审查（规则 + 人评），输出可读报告
```

### L1 规划层：产物必须是"可检查的表"

规划的价值不在于"先想一遍"，而在于**让结构决策在写之前就被显式化、可被程序检查**。因此规划的产物不能是散文式大纲，必须是表：

**场景卡（scene card）**

| 字段 | 例 | 为什么需要 |
|---|---|---|
| 场景目标 | 让她决定去赴约 | 防止"为了文采而跑题" |
| 视角 | 第三人称限知（她） | 视角漂移是最常见的叙事错误 |
| 进入情绪 / 离开情绪 | 警惕 → 松动 | 差值决定场景是否有推进（对应 NF 的"情感强度分布"） |
| 读者已知 / 未知 / 本章应知 | 已知：他撒过谎；未知：为什么 | **信息释放表**，直接压制 P6 过度解释 |
| 禁止出现的解释 | "她其实是因为…所以…" | 显式写"不许解释"，比写"要含蓄"有效 |
| 结构预算 | 长句≥2、短句≥3、零主语链≥1 | 见 L2 |

### L2 配额层：预算 = 分布目标 + 硬上限

不要写"禁止使用 XX 句式"（会立刻生硬）。写**预算**：

```
sentence_len_cv_target : 体裁基线 ± 20%      # 目标区间
clause_len_entropy_min : 体裁基线的 5% 分位   # 下限
skeleton_reuse_max     : 最近 20 小句内同骨架 ≤ 2 次（硬上限）
parataxis_ratio        : 流水句占比目标区间 [0.25, 0.55]
explicit_emotion_max   : 每千字显式情绪词 ≤ N（体裁相关）
four_char_idiom_rate   : 目标区间（不是越低越好）
```

**配额不是通过"生成时禁止"实现的**（无法做到），而是通过 L4 的**重排 + 局部重写**实现。

### L3 生成层：k 候选 + 明确的差异要求

- k = 3（成本/收益折中；Guo 的甜点是温度 0.6，本项目在 0.7–0.9 之间做候选，最后按质量选）。
- 三个候选必须**用不同的开头策略**触发（这比给三次同一 prompt 更有效）：候选 A 从动作切入、B 从环境细节切入、C 从对话切入。这相当于把"叙事视角的多样性"前置到采样阶段。
- 单段长度控制在 300–600 字：更长会让结构塌回默认（Reinhart 的 500 词续写实验正是这个长度，且已显现偏差）。

### L4 修整层：评分函数（可解释、可调）

```python
score = w1 * coverage_gap      # 与体裁基线的结构覆盖缺口（越低越好）
      + w2 * skeleton_reuse    # 最近窗口内骨架复用次数（越低越好）
      + w3 * style_drift       # 与目标人物/文体档案的功能词距离
      + w4 * concreteness      # 具体名词/专名密度（越高越好，抑制抽象化）
      - w5 * oddity            # 生硬惩罚（§2 F2 的三项）
```

默认权重建议（**待标定**，不是结论）：w1=1.0, w2=0.8, w3=1.2, w4=0.5, w5=1.5。**w5 权重高于其它**，因为生硬的代价大于平庸的代价。

局部重写规则：
- 只重写"命中违规"的小句及其直接依赖的小句（≤3 小句）；
- 改写时必须给出**具体约束**（"这句的骨架与小句 3 相同，换一个信息组织顺序：把'看窗外'换成环境在先、动作在后"），而不是"改得更自然"；
- 改后必须通过一致性检查（指代、时态、事实）。

### L5 审查层：只做守门，不做裁判

- 硬门禁（必须过）：一致性、事实、人物卡冲突、明显的重复。
- 软报告（供作者看）：结构指标、嫌疑簇 diff、与体裁基线的偏差表。
- **不做**："AI 概率分数"作为质量分（`linguistic_analysis.md` §5.4 已论证）。

## 4. 中文专项：把"意合"用起来

中文文学最重要的结构资源是**流水句 + 零主语 + 短句截断**。AI 文本的问题不是"没有长句"，而是**节奏均匀**。因此中文策略必须是：

### 4.1 三拍结构（长—长—短）

汉语叙事的经典节奏是"铺垫两句长、收一句短"。可操作化为：

```
段落内小句数序列：建议出现至少一次 3-5 小句连缀（长）+ 至少一次 1-2 小句独立（短）
判别：句子长度序列的 lag-1 自相关应接近 0 或为负（人类常见交替），
      若显著为正（>0.3）则判为"等速推进"（AI 常见）
```

这条**尚未验证**，属于待测假设（列入 `evaluation_framework.md` 实验 3）。

### 4.2 零主语链

允许并鼓励连续 2–5 个零主语句（话题链），这是汉语叙事的核心手段，也是 AI 最不会做的一件事（模型倾向于补齐主语以"清楚"）。可测：`ZERO` 标记的连续长度分布（`syntax_fingerprint.md` §1.2）。

### 4.3 对话自然度

中文对话的机械化表现为：每句都完整、都带主语、都用"说道"、都恰好回答对方问题。人类对话的特征是：打断、答非所问、省略、语气词错位。可操作化为配额：

```
完整主谓句比例 ≤ 60%
"说/道/问" 引导语密度 ≤ 1/3 对话轮
每 10 轮对话至少 2 轮"未直接回应"
语气词（呢/吧/啊/嘛/罢了）密度落在体裁区间
```

### 4.4 人物语言卡（见 `agent_architecture.md` §Character Voice Engine）

每个主要人物维护：句长偏好、词汇域、口头禅、禁忌词、句法复杂度、语气词偏好、回避策略（遇到压力时是"沉默/反问/绕开"）。生成对话时注入**当前说话人 + 对话对象**两张卡，而不是"注意人物性格"。

---

## 5. 多语言：不能直接搬

- 英语：可直接用 Reinhart 等（2025）公布的 **Biber 66 特征人类率表**（Table S5 按体裁给出）作为基线，把"该减的减 60–80%、该补的补回"作为预算。这是目前**唯一有公开数值的现成基线**。
- 中文：**没有对应基线**（`literature_review.md` 缺口 1）。必须先自建（`evaluation_framework.md` 实验 0）。
- 其他语言：Stanza 支持 70+ 语言（Qi 等 2020），但**本项目的归一规则 N1–N10 是汉语专用**，不可直接迁移。多语言需各自建归一表，成本高，建议 v3 之后。

## 6. 可运行伪代码（dsh 工具形态）

```python
# 由 dsh 插件注册为工具 write_scene 的内部实现
def write_scene(scene_card, style_profile, state):
    budget = load_budget(style_profile.genre)          # L2
    cands = []
    for opener in ("action", "environment", "dialogue"):   # L3
        cands.append(llm_generate(scene_card, opener, n=1, temp=0.8))

    best, best_score = None, -1e9
    for c in cands:
        fp = fingerprint(c)                            # 见 syntax_fingerprint.md
        s = score(fp, budget, style_profile, state)    # L4
        if s > best_score: best, best_score = c, s

    for _ in range(2):                                 # 最多两轮
        v = violations(fingerprint(best), budget)       # 只找结构违规
        if not v: break
        for clause in v[:3]:                            # 每次最多改 3 个小句
            best = local_rewrite(best, clause, anchor=state, constraint=v[clause])
        if consistency_break(best, state):              # F3 防线
            best = previous_best; break

    return best, report(fingerprint(best), budget)      # L5 软报告
```

## 7. 这些策略可能在哪里失败

1. **k 候选的 token 成本**：3 候选 + 2 轮修整 ≈ 5–7 倍单次生成成本。若按每千字计，长篇不可承受。→ 建议：**只在关键场景（开场、转折、情绪高点）用满流程**，其余用单候选 + 轻量检查。
2. **结构评分与文学质量的相关性未验证**：所有 w1–w5 权重都是猜的。**必须先用人工标注的 100 个段落标定权重**，否则就是在优化一个不知道是什么的东西。
3. **局部重写可能破坏语感**：改一个小句会改变节奏。→ 规则：单个场景的总改动 ≤ 20% 小句数，超过则整段重生成而不是逐句改。
4. **动态上下文污染**：把"已用骨架"注入上下文，模型可能开始**谈论**句式（"我注意到用了三次…"）。→ 规则：结构信息只以**结构化字段**注入（JSON 片段），不用自然语言描述。
5. **对"专业文学基线"的依赖**：NF 的研究显示，用网文/公众号当人类基线会**低估扁平化**（因为这类文本本身更接近模型默认节奏）。→ 本项目的参考文献基线必须是**严肃文学 + 分体裁**，而不是随便找的网络文本。
